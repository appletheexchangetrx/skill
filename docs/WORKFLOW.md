# Operating Workflow

1. Discover accessible GitHub repositories and let the user select one.
2. Discover branches and let the user select the target.
3. Inspect repository metadata and permissions.
4. Detect React/Vite, package manager, scripts, integrations, and deployment.
5. Ask Repository Only or Repository + Supabase.
6. If Supabase selected, match detected project configuration to connected projects and ask user to confirm.
7. Inventory the complete repository and create a coverage ledger.
8. Complete comprehensive audit before any deep module audit.
9. Deep-audit modules and cross-module flows.
10. Consolidate findings, priorities, score, and verification gaps.
11. Ask evidence-based questions and offer prioritized work groups.
12. For an approved group, prepare plan and acceptance criteria; ask implementation approval.
13. Create a dedicated branch, implement, test, inspect diff, and open PR.
14. Stop before merge until explicit user approval.
15. With report-save approval, create history report and update latest report in the audited application repository.
16. Re-audit after changes and compare findings.
